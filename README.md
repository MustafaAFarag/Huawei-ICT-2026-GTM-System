## Run


Open `http://127.0.0.1:8765`. SQLite persists at `data/command-center.sqlite`. To rehearse from a fresh database without deleting an existing demo, run `python3 -m gtm.server --db /tmp/gtm-rehearsal.sqlite --port 8766` with a new path. This server binds loopback and is a local reviewer tool without authentication; client scoping is tested but is not production access control.

This session's sandbox prevents opening sockets: `PermissionError: [Errno 1] Operation not permitted`. Therefore HTTP request handlers were tested directly, and the browser used replayed responses generated by the actual Python workflow. A running-server transport test remains outstanding. ## What works

- Two client workspaces, three seeded campaigns, an empty-state path and configurable client offers/brand profiles.
- CSV import with column mapping, source-row ledger, professional-identifier reconciliation, ambiguous-identity holds and atomic import retries.
- Client exclusions and opt-outs; conflicting evidence and role-fit holds; per-channel missing-data and sender checks.
- Dated source review, transparent account–role–offer ranking, approved-only lexical retrieval and bilingual template drafts. Imported evidence cannot approve itself.
- Human review of all three sequence touches; copy/offer/evidence changes invalidate approvals and cancel scheduled fixtures. Stale versions cannot overwrite newer copy.
- CSV/XLSX preparation, Smartlead fixture payloads and Dripify custom-message-field CSVs. Blocked contacts retain reasons and contain no outbound copy. Calls/WhatsApp produce manual tasks.
- Campaign collision holds, scheduled/sent/failed/cancelled action history, client-scoped reply cancellation and duplicate event reconciliation.
- Four editable HTML asset types, English/Arabic output, Chromium print-to-PDF, record-backed charts and locally generated deterministic QR codes.

All professional records in the seed data are original synthetic fixtures. New imports retain their declared origin or `imported-unverified`. The baseline has no commercial-response prediction and no verified service-specific case studies. Local HTML edits never alter approved campaign copy.

## Demonstration

1. Select **Regional growth · successful path** and open Noura's account review.
2. Review the source, generate bilingual copy, inspect all three touches, check the claims review box and approve the current version.
3. Prepare email in **Preparation**. Noura is eligible; unreviewed Maya remains held. Repeat the operation to demonstrate idempotency.
4. Generate a brief, one-pager, summary and card in **Branded assets**. Open HTML to edit, save or print.
5. Save a copy revision; previous approval and scheduled fixtures become invalid. Reapprove the saved version to prepare it again.
6. Record a simulated reply. All later touches for that contact in this client workspace are cancelled. Retry the same event ID to demonstrate reconciliation.
7. Select **Account outreach · exceptions** for duplicate rows, missing email, conflicting bank evidence, an existing client, an opt-out and a sender hold. Switch to Client B to show separate records.
8. **Client knowledge** edits client-specific services, role vocabulary, brand colors and the networking URL. No placeholder example.org URL should be presented as Lara's actual profile.

[Samples](samples/) contain eight editable bilingual HTML documents, CSV/XLSX and a paused Smartlead fixture. Generate them with `python3 verification/make_samples.py`. They demonstrate synthetic workflow behavior only.

## Verify

```bash
python3 -m unittest discover -s tests -v
node --check web/app.js
python3 verification/build_browser.py
python3 verification/make_samples.py
```

The generated `verification/browser-check.js` can be run by the Playwright browser tool. It replays actual domain transitions and checks mutation payloads, AR/EN layout, error recovery and empty states. `verification/check-twenty.cjs` accepts a path to an installed TypeScript module for syntax and metadata-relationship checks; it does not emulate a real SDK typecheck.

Evaluation preparation: `python3 evaluation/prepare.py --output evaluation/data`. This creates 80 synthetic company packs and 480 **unlabelled** judgment slots with a 56/12/12 company split. Complete independent reviewer/adjudication records and replace synthetic evidence before making quality claims. `predict.py` supports rules and frozen local neural weights; `train.py` is bounded to 200 steps and never uses test labels for checkpoint selection. Neural code was not run here.
